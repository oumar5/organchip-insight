## Summary (265 words)

OrganChip Insight is a local, reproducible analysis workspace for bright-field
organ-on-chip microscopy. It turns an image folder into a traceable experiment:
the user imports PNG, JPEG, or 16-bit TIFF files, reviews accepted and rejected
items, runs CPU inference, inspects segmentation overlays and per-image
measurements, and exports JSON and CSV evidence. The default adaptive engine
requires no learned weights and remains usable offline. Every engine is exposed
through a registry that states its availability, provenance, intended use, and
scientific limits.

The project treats credibility as a product feature. Public BBBC019 and
BBBC038 benchmarks are generated by versioned scripts, displayed with
intervals and computational cost, and linked to SHA-256-identified reports.
The interface calls detections “connected components,” because no organ-on-chip
instance annotation validates them as cells. A bounded preregistered BBBC038
audit caused us not to promote µSAM despite its stronger BBBC019 foreground
score: it failed two of three instance-level promotion criteria and required
about 8.9 GB of memory in the measured CPU environment.

We also investigated binary image-quality classification with MobileNetV3.
Acquisition mode, culture age, and lineage created strong shortcuts. Grouped
splits, metadata-only comparators, mode-specific metrics, and preregistered
ablations showed that no robust quality signal independent of acquisition and
culture metadata was demonstrated. The frozen test set was therefore never
opened. The selected CNN can only run as an optional ONNX demonstrator that
always abstains, labels its softmax as uncalibrated, and never makes an
automatic good/bad decision.

The result is not a diagnostic system. It is an auditable Tool & Platform for
quality-aware microscopy workflows, designed to make useful outputs,
provenance, uncertainty, and negative findings visible together.

## Evidence and limitations

- BBBC019 foreground segmentation and BBBC038 instance results are external
  validation aids; they do not validate cell counting on the competition
  organ-on-chip images.
- The CNN study is closed. No configuration passed the preregistered minimum
  balanced accuracy in both acquisition modes, and the test split remains
  unopened.
- Connected-component areas and diameters are in pixels because no physical
  calibration is available.
- The current SQLite and filesystem architecture targets local or
  single-instance use, not multi-tenant clinical deployment.
- No personal, clinical, or private data is used. The platform must not be
  interpreted as a diagnosis or an automated biological conclusion.

## Reproduction

```bash
cp .env.example .env
docker compose up --build
```

Open `http://localhost:8080`. Verification:

```bash
make check
make test-e2e
```

The complete input/output contract, data manifests, checksums, experimental
protocols, and dated decision records are available in the public repository.

## AI, data, models, and licences

The product does not call an LLM or commercial API. AI assistants supported
code, test, documentation, and literature-review work under human review; all
reported measurements come from versioned scripts. The data sources are the
CC-BY-4.0 OOC Image Dataset, CC-BY-3.0 BBBC019, and CC0 BBBC038. The isolated
µSAM benchmark uses MIT code and CC-BY-4.0 weights. The optional MobileNetV3
demonstrator uses torchvision and ImageNet weights under BSD-3 terms. Exact
versions are locked in `backend/uv.lock`, `frontend/package-lock.json`, and the
experiment environments.
