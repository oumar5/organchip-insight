## Règles

1. Séparer les faits observés, les hypothèses et les décisions.
2. Ne jamais inscrire une métrique qui ne vient pas d'un script versionné.
3. Noter les versions des données, modèles, dépendances et matériels utilisés.
4. Relier chaque résultat à une commande, un artefact ou un commit reproductible.
5. Documenter aussi les échecs, les limites et les changements de direction.
6. Corriger une ancienne entrée par un addendum daté plutôt que d'effacer
   silencieusement l'historique.

Une entrée de ce dossier n'est pas une promesse produit. Elle décrit l'état des
connaissances à une date donnée.
